# Jump and Run

A small 2.5D platformer the user is building to **learn Unity**. When you change code, explain the Unity idea behind it (for example interpolation or why physics runs in FixedUpdate). Don't just make silent fixes.

## Working mode
- **Never assume. Always ask, interview style.** Before you implement or decide anything (design, gameplay, code structure, naming, assets), ask the user with a set of concrete options (use the AskUserQuestion tool). Put the option you **recommend first** and mark it as recommended. Only act once the user has chosen.
- **Git**: local repo (branch `main`, no remote, no LFS yet; set up LFS before the first large binary like models/textures/audio). **Commit after every finished work item**, as soon as it compiles cleanly and is done on your side, without waiting for the playtest. Tuning or fixes after the playtest get their own small commits. Commit messages in **English**, short and imperative. `.gitignore` covers `Library/`, `Temp/`, `Logs/`, `UserSettings/`, `obj/`, `*.csproj`, `*.slnx`, `.DS_Store`.

## Theme (decided as of 2026-10-23)
Only decided things go here, no loose ideas.
- **Pizza delivery**: the player is a pizza delivery guy carrying a pizza carton. Each level he picks up a new pizza at his **pizzeria** (start, a house in the background) and delivers it to a **customer** (goal), who is super happy and starts dancing.
- **Level 1 = city.** Enemies are dogs (instead of the red `Enemy`). Platforms are city objects (benches, balconies, ...).
- **Heat meter + tip**: the pizza cools down over time (a heat bar at the top center, no seconds shown). The remaining heat on delivery sets the tip as **1–3 gold coins** (heat thirds: ≥ 2/3 = 3, ≥ 1/3 = 2, > 0 = 1). At 0: "Pizza's cold!" for 1.5 s, then the level restarts. Respawning costs no extra heat (the lost time is the penalty). The TimeBonus power-up warms the pizza back up and **may go above 100%** (buffer, shown as a pulsing overlay on the bar). Keep-warm time: level 1 = 60 s, level 2 = 80 s (scene overrides on `levelTime`, still to be tuned).
- **Delivery**: player frozen (input off, gravity/platform keep going), panel "Delivered!" + coins, Jump continues to the next level.
- **Steam** on the carton fades evenly with the heat.
- **Customer** (goal): stands in front of a front door, sways while waiting, waves once the player is < 6 m away. On delivery the carton hops over in an arc into their hands, then they dance **by tip**: 1 coin = sway, 2 = bounce + alternating arms, 3 = hop + spin + arms overhead. Shirt/skin color per level in the Inspector. The "Delivered!" panel is compact at the top (no darkening), so the dance stays visible.
- **Dog**: patrols (2 m/s), when the player steps onto its platform it stops, a "WOOF!" bubble + hop for 0.5 s (warning, every time again), then charges at 6 m/s (player 7, you can get away). Fur/ear colors per dog in the Inspector.
- **Street with cars** (planned): fixed rhythm; the warning is that you can see the cars approaching from the background (+Z) before they cross the player's lane toward the camera.
- In-game texts in **English**.
- **Dog stomp**: no squashing. The player still bounces, the dog gets dizzy (stars over its head, 1 s), runs into the background (+Z, 12 m) and disappears, then comes back on `LevelReset`.
- **Placeholder look**: until there's a real model, the player stays a **sphere** (collider radius 0.5; physics unchanged) and carries a red carton with a white lid (`Pizza Carton` → `Box`/`Lid`, materials `PizzaRed`/`PizzaWhite`, no colliders).

## Setup
- Unity **6000.6.2f1** (Unity 6), URP 17.6, new **Input System** 1.20 (read directly with `Keyboard.current` / `Gamepad.current`, so the `InputSystem_Actions.inputactions` asset isn't wired up yet).
- Code comments, Inspector headers and tooltips are in **German**. Keep it that way.
- Scenes: `Assets/Scenes/levels/level01.unity`, `level02.unity` (`SampleScene` is the template leftover).
- Physics: 50 Hz fixed timestep (0.02), default gravity -9.81. The player turns off Rigidbody gravity and applies its own.
- Layer 3 = `Ground`, the player's `groundLayer` for ground checks. The player has the `Player` tag.
- **Unity MCP** (official, package `com.unity.ai.assistant` 2.20.0-pre.2, pre-release; registered in `.mcp.json`): `Unity_RunCommand` runs C# in the open editor (class `internal class CommandScript : IRunCommand`; `System.Reflection` is blocked; `result.Log` doesn't understand format specifiers, so use `$"{x:F2}"`), `Unity_GetConsoleLogs`, camera/scene captures (they don't include a Screen Space Overlay UI). While Unity recompiles, the bridge drops out briefly ("Unity not detected"), so wait and try again.
- **Enter Play Mode Options are on** (Domain Reload + Scene Reload disabled): statics survive between Play sessions (e.g. `GameManager.Instance` points to the old object after Stop, and static events keep listeners that aren't removed in `OnDestroy`). After Stop, don't read values through `Instance`.
- Screenshots of the game camera via the MCP: render `Camera.main` into a RenderTexture in `RunCommand`, save it as a PNG under `Temp/` and read it (`Unity_Camera_Capture` without an ID only shows the Scene View; `GetInstanceID()` is a compile error in 6.6, it's `GetEntityId()` now). The **relay shuts down after 180 s without MCP activity**; after that, calls hang and the user has to run `/mcp` → Reconnect.
- Play mode tests through the MCP: the editor usually isn't focused, so frames won't advance unless `Application.runInBackground = true`. **Caution: in the editor this writes `PlayerSettings.runInBackground` into `ProjectSettings.asset` (persistent!).** After testing, reset it with `PlayerSettings.runInBackground = false; AssetDatabase.SaveAssets();` (the project value is `false`) and check `git diff ProjectSettings/`.
- TextMeshPro Essential Resources are imported (`Assets/TextMesh Pro/`).

## Gameplay structure
- **2.5D**: the level runs along +X. The player Rigidbody has **position Z frozen** and all rotation frozen. `PrefabGridEnforcer` (editor) snaps prefabs to a 1x1 grid at Z = 0.
- `PlayerController`: Rigidbody movement (velocity set directly), Celeste/Hollow-Knight-style jump: gravity derived from `jumpHeight`/`timeToApex`, stronger gravity when falling, jump cut on release, apex hang, coyote time and jump buffer. Powerups call `ApplySpeedBoost` / `ApplyJumpBoost` (the latter multiplies jump velocity).
- `ThirdPersonCamera`: follows the player in `LateUpdate` with a world-space offset, separate SmoothDamp for horizontal and vertical, fixed rotation.
- `PointToPointMover`: the shared A↔B movement (used directly by the **Flying Enemy** prefab). `MovingPlatform` is an empty subclass of it, so the player recognizes platforms. Movement details:
- `MovingPlatform`: kinematic Rigidbody, moves A↔B with ease in/out (`easingStrength`, peak speed = `speed` × strength; `speed` = average speed), waits `waitTime` at each end, starts from its editor position (projected onto A→B, heading toward B first), and only waits at start if it sits on an endpoint. A/B are children of the platform (`moving platform start/end`) and their positions are read once in `Start`. It does **not** move passengers itself; it exposes `Velocity`, and `PlayerController` adds that velocity to its own (`carryVelocity` stays while airborne, so jumps keep platform momentum; rising platforms add their upward speed to the jump). Never move the dynamic player with `MovePosition`/teleporting, because that fights the physics and kills jumps.
- `PowerUpShine` (on the Player prefab) + `Assets/Shaders/PowerUpShine.shader` (hand-written URP HLSL, additive fresnel rim + sweeping stripe): while a boost is active, it attaches the shine material as an extra material on the renderer, colored per power-up type, and blinks shortly before the boost runs out. `PlayerController.ApplySpeedBoost/ApplyJumpBoost` trigger it.
- Prefabs are capitalized (`Platform Big`, `Moving Platform Small`, `Dog`, `Checkpoint`, `Goal`, `PowerUp`, ...). Paths in editor scripts must match exactly.
- Enemy prefabs: `Dog` (formerly `Enemy`, renamed with the same GUID; `EnemyPlatformPatrol` + `Dog`, needs `WaypointA/B` on its platform) and `Flying Enemy` (purple, `PointToPointMover` between its children `Point A`/`Point B`). Both use `EnemyDamage`.
- `EnemyDamage`: a contact from above (direction to player `y >= stompDirectionThreshold`, player not rising) is a **stomp**. The enemy is disabled immediately (collider plus all other scripts), and `PlayerController.StompBounce()` bounces the player (higher while jump is held). If the enemy has a component with **`IStompHandler`** (e.g. `Dog`), it stays enabled and decides the reaction itself in `OnStomped()` (and has to call `SetActive(false)` at the end); otherwise it squashes flat. Any other contact calls `GameManager.RespawnPlayer()`.
- `EnemyPlatformPatrol` hooks: `flipTarget` (what gets mirrored via scale.x; empty = itself; for the dog it's `Body`, so collider/Rigidbody stay unmirrored), `IsChasing` (player on the same platform), `HoldPosition` (stand still but keep facing the player).
- `Dog` (built by `DogSetup`, **Tools > Jump and Run > Build Dog Prefab**): bark coroutine on the rising edge of `IsChasing` (sets `HoldPosition`), run animation (legs/tail) from the position change since the Rigidbody is kinematic, `OnStomped` → dizzy → turn -90° around Y → run to +Z → `SetActive(false)`. The `Woof Bubble` (TextMeshPro 3D + quads) and `Dizzy Stars` hang on the root, **not** on `Body`, so the text is never mirrored. Both are saved inactive in the prefab. Colors via MaterialPropertyBlock on `Dog.mat`. The physics is still SphereCollider r = 0.5.
- **Level reset on respawn**: `GameManager.RespawnPlayer()` raises the static event `GameManager.LevelReset`. Subscribers (subscribe in `Awake`, unsubscribe in `OnDestroy`): `EnemyDamage` revives squashed enemies, `EnemyPlatformPatrol` and `PointToPointMover` go back to their start positions, `PowerUp` reactivates (`respawnOnLevelReset`), and `PlayerController` clears boosts, shine and platform momentum. Enemies and power-ups are therefore only **deactivated** (`SetActive(false)`), never `Destroy`ed. Keep it that way for new resettable objects.
- `PizzaCarton` (on `Pizza Carton`, child of the Player): mirrors its local X offset in `LateUpdate` based on `PlayerController.FacingDirection` (+1/-1, set from the world-space input direction, not from velocity, so platforms don't turn the player; it keeps its last value while standing still). Instant flip. It also controls the `steam` particle system: emission rate and start alpha × `Clamp01(HeatPercent)` (Inspector values = full heat).
- `GameManager` (singleton): `levelTime` = keep-warm time, `RemainingTime`/`HeatPercent` (can be > 1), `CoinsForHeat`, `TwoCoinHeat`/`ThreeCoinHeat`. `DeliverPizza()` (called by `LevelGoal`; returns false if the level is already over) and pizza going cold set `LevelFinished`, freeze the player (`PlayerController.Freeze()`) and raise the static events `PizzaDelivered(int coins)` / `PizzaCold`. While `LevelFinished` is true, `RespawnPlayer()` is ignored. `AddTime()` is intentionally not capped.
- `LevelGoal`: after a delivery it waits `continueInputDelay` (0.5 s), then for Jump (Space / gamepad South) and loads the next level. On the last level it only logs.
- `PizzaHud` (on the `HUD` prefab, uGUI + TextMeshPro): heat bar (width via `anchorMax.x`, color from gradient, overheat overlay for > 100%, ticks at the coin thresholds), `Delivered Panel` with 3 coins (built-in `Knob` sprite, popping in one by one), `Cold Panel`. Both panels are saved **inactive** in the prefab (otherwise they cover the Game view in edit mode). Display only, no GraphicRaycaster/EventSystem needed.
- `PizzaHeatSetup` (editor, **Tools > Jump and Run > Pizza Heat**): `Create HUD Prefab` (builds the HUD in code → `Assets/Prefabs/HUD.prefab`; needs the TMP Essential Resources), `Add HUD to Active Scene` (prefab instance + save scene), `Add Steam to Player Prefab` (particle system `Steam` under `Pizza Carton`, URP `ParticlesUnlit`, world simulation space). All re-runnable; existing objects get replaced. Changes to the HUD/steam layout belong in this tool, otherwise the next run overwrites them.
- `Customer` (on `Goal/Customer`, built by `CustomerSetup`, **Tools > Jump and Run > Build Customer into Goal Prefab**, replaces the old pole `Visual`): states Waiting → Receiving → Dancing, listens to `PizzaDelivered`. Moves only `Rig` (the root stays put); arms swing via `Arm Pivot L/R` (shoulder pivot, rotation around Z: 0 = hanging, the -X arm goes up with negative angles). On handoff it disables `PizzaCarton` (otherwise LateUpdate would put it back) and reparents the carton to `Hands Point`. Colors through a **MaterialPropertyBlock** on the shared `Customer.mat` (white), also live in edit mode via `OnValidate`. Materials `Customer`, `House Wall`, `Door`, `Door Knob`. No colliders except the Goal trigger.
- Other scripts: `Checkpoint`, `KillZone`, `PowerUp` (types Speed/Jump/TimeBonus), `EnemyPlatformPatrol`.
- Editor tools under **Tools > Jump and Run**: `ObstacleCourseBuilder` generates the levels from `Level1Layout`/`Level2Layout` (gaps measured from edge to edge). `LevelEssentialsSetup` copies Player/GameManager into level 2. `LevelCleaner` (**Clear Level (active scene)**) deletes platforms, enemies, checkpoints and waypoints but keeps Player, StartPoint, GameManager, camera, Goal and KillZone. The levels are hand-built (as of 2026-10-02): level 1 is finished, and level 2 was reset from a copy of level 1 (course removed; Player/GameManager/Goal are prefab instances). The `ObstacleCourseBuilder` layouts are outdated. Don't run them, because they would overwrite the hand-built level.

## Pitfalls
- Jump reach limits level design. Right now that's about 3.2 m high and about 5.5 m far at `moveSpeed` 7. If you change the jump or moveSpeed, check the gaps in `ObstacleCourseBuilder` (level 2 has 5.5 m gaps with a 1 m step up).
- The player collider gets a **zero-friction PhysicsMaterial** in `Awake`. With the strong custom gravity, default friction (0.6) almost cancelled out walking acceleration. Don't remove it.
- "Grounded" for jumping = ground check hit + no jump in the last 0.1 s (`GroundLockAfterJump`). **Don't** add a vertical-velocity condition. On moving platforms the player's vy never exactly matches the platform's (easing, solver), so jumps got dropped.
- The player Rigidbody needs **Interpolate** (set on the prefab). Without it the camera jitters, because physics runs at 50 Hz and rendering doesn't.
- Serialized values in prefabs/scenes override code defaults. If you change a default in code, also check the prefab (`Assets/Prefabs/Player.prefab`) and scene overrides.
- New `.cs` files aren't in `Assembly-CSharp.csproj` until Unity re-imports (the csproj lists every file). For a pre-check without the editor, add a `<Compile Include=...>` line by hand.
- Verify it compiles without the editor: `/Applications/Unity/Hub/Editor/6000.6.2f1/Unity.app/Contents/Resources/Scripting/DotNetSdk/dotnet build Assembly-CSharp.csproj` (the CS0649 warnings for `[SerializeField]` are normal). Game feel can only be tested in the editor, so ask the user.
